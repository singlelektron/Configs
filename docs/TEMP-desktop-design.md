## 先读这一页

**目标：工作时是一套清晰、统一、半透明的深色工作站；打开桌面、听音乐或等待任务时，呈现有二次元气质的现代科幻界面。简约的是信息和操作，华丽的是材质、构图和少量关键转场。**

- 保留 Niri 横向滚动、用户已经习惯的快捷键、现有字号与显示缩放，以及 Kitty / Neovim 的原生工作流。
- 第一优先级不是增加特效，而是把顶栏、启动器、通知、Wi-Fi / 有线网络、蓝牙、声音、常亮和会话操作做成同一套可用界面。
- 推荐从 main 开始重整桌面外壳，保留已有部署与编辑器基础；旧 draft PR #3 保留为可回溯的功能参考，不直接丢弃其中验证过的行为。
- 统一桌面基础首选验证 **Noctalia v5 当前维护版本**，以配置、主题和受支持扩展定制；不要照旧版教程把 v5 当成 Quickshell 配置。若关键体验或维护边界不满足，记录原因后才采用现有 Quickshell 的统一重构路线。
- 个性集中于一套原创视觉语言、静态高质量二次元壁纸、按需打开的音乐展示界面和终端仪表台；不是安装某个 shell 的默认主题就算完成。
- 音乐播放生命周期与华丽 UI 分离；顶栏与播放器界面控制同一个真实播放源。先证明关 UI 不断音、重开不重播，再做高级动效。
- 不增加一套“工作 / 娱乐 / 性能”模式管理负担。不同表现来自界面是否展开、是否可见，不自动猜测用户是不是在工作或等待 Codex。
- 先完成三种状态的可交互视觉样片，再扩展功能；不能只提交更多配置文件和 headless 测试就宣布设计成功。

## 3. 推荐视觉方向：夜航档案室

这是一项待通过实机样片确认的艺术方向，不是用户已经选定的品牌、色号或某款游戏的完整 UI。

想象一个深色、安静的未来档案室：二次元插画提供情绪，烟色玻璃提供层次，细线和精确排版提供秩序；打开音乐时，封面像一张实体收藏品从界面中浮出。工作窗口不变成游戏 HUD。

### 3.1 视觉锚点

- **一个主要画面，而不是很多抢眼小挂件。** 空桌面以壁纸为主；音乐展开时以封面 / 专辑为主；设置界面以当前操作为主。
- 基底采用中性墨蓝灰 / 炭灰，辅以淡紫主强调和少量冷青状态色；二次元感来自图像与构图，不把整个系统涂粉。
- 主要平面使用细边、轻阴影、克制圆角和明确对齐；音乐卡片可以更立体。桌面不是十几个没有层级的胶囊拼贴。
- 科幻感来自细线、留白、少量索引标记和连续转场，不来自随机编号、假遥测、装饰警告、乱码或满屏网格。
- 界面沿用英语为主、中文正常输入与显示；不用长英文缩写替代本来清楚的功能名称。

初始色彩锚点可用：背景 `#11151D`、面板 `#1B2230`、正文 `#E5EAF3`、次级文字 `#A9B4C7`、主强调 `#B6ABEF`、次强调 `#84CFD2`。这些是样片起点，不是禁止设计师调整的硬编码合同。错误、警告、Git 增删保留独立语义色，不全部重映射成强调色。

字体沿用用户当前满意的等宽字体及尺寸；桌面正文用清晰的无衬线字体和可靠中文回退，装饰标签可少量等宽。共享间距、圆角、图标笔画、文字层级和状态规则；按各应用支持方式映射，不靠到处写同一组 CSS 颜色伪装成设计系统。

### 3.2 透明、壁纸和亮度

保留 Kitty 半透明：先以旧 PR 的 `0.86` 为对照起点，而非强制恢复 main 的较高不透明度。编辑区、侧栏、浮层不必同样透明；正文、光标与诊断不可一起变淡。阅读体验覆盖代码、中文、Markdown 正文、diff 和无高亮的终端输出。

优先用静态高质量壁纸，画面允许角色、建筑与夜间光影，工作区中央避免刺眼的大面积高亮。选择适合 4K 构图的素材，记录真实分辨率与裁切方式，不把低分辨率放大说成原生 4K；不沿用作者不明的素材作为公开默认包。个人壁纸保存在仓库外。

Niri 官方文档已记录从 26.04 引入背景效果；实施时仍必须读取本机版本并验证。优先评估静态壁纸 + xray 模糊，而不是全屏动态壁纸叠实时透射；xray 可以复用壁纸模糊结果，非 xray 的移动背景更昂贵且有实验性限制。[Niri Window Effects](https://niri-wm.github.io/niri/Window-Effects.html)。没有可用模糊时提供稳定的半透明 / 深色材质退路，不换合成器来追特效。

### 3.3 参考的正确用法

[Rhine Music Demo](https://github.com/RonaldDeng/Rhine-Music-Demo) 与其 [DESIGN.md](https://github.com/RonaldDeng/Rhine-Music-Demo/blob/main/DESIGN.md) 适合借鉴的是玻璃专辑、抽取与归位、连续空间关系、细线与中英文层级。它的文档说明了与 RhineLabUI 及《明日方舟》莱茵生命特别映像的关系。

不照搬品牌、角色资产、配乐或每次启动的长片头；不因为代码许可宽松就推定图像、字体和音频可任意再分发。参考项目以本地音乐 / 浏览器界面为主要场景，不能因此把用户现有流媒体需求改成只听本地文件，也不假定它满足 Arch、MPRIS 或关闭 UI 后继续播放的要求。本次读了说明与设计文档，未运行该项目或完成其动画的实机视觉验收。

## 4. 同一种桌面，三种自然展开层次

以下是呈现层次，不是要求用户切换的三个模式。

| 层次 | 用户看到什么 | 什么不应该发生 |
| --- | --- | --- |
| 日常工作 | 紧凑顶栏、安静的半透明终端、清晰窗口焦点与一致控件；壁纸在背景提供气氛。 | 不持续跑频谱、粒子、跑马灯；不因 Codex 输出 / 空闲时间自动改布局、壁纸、颜色或通知。 |
| 操作展开 | 点击声音、控制中心或音乐后出现相同材质的轻量面板；结束后自然收起。 | 不推挤工作窗口；不打开好几个互不协调的设置程序；不重启整套桌面。 |
| 主动欣赏 | 用户打开音乐展示页或终端仪表台；有更大的封面、玻璃层次、克制景深和可中断的转场。 | 不自动覆盖编辑器，不抢焦点；不要求开启它才能播放音乐或管理设备。 |

空桌面无需再塞天气、待办、语录和重复时钟。华丽应来自画面质量，不是把剩余空间填满。

## 5. 布局和交互

### 5.1 顶栏

推荐逻辑顺序：

```text
[控制中心 / 工作区 / 当前应用]   [封面 · 曲名 · 播放]   [更新 / 音量 / 日期时间 / 收起项]
```

使用共同的视觉基线与材质，可分区但不要让三个区域看起来属于三套主题。保持当前合适的字号、点击尺寸与工作区高度，先不凭空缩小全部控件。

当前应用名称有长度上限，完整信息放悬浮提示；歌曲和时钟变化不推动其他元素。工作区可点击，已有图标 / 文字承担入口，不额外增加成排按钮。音量支持点击与滚轮，播放键独立可点击，封面 / 曲名展开轻量音乐面板，其中有明确的“打开音乐界面”动作。

音乐未播放时仍保留紧凑入口和真实停止 / 暂停状态，不编造曲目。网络、蓝牙、托盘和硬件详情默认在展开层；断网、静音等确需注意的状态可有小而真实的提示。更新入口保留，失败 / 未检查不能显示成零更新，不自动升级，不把 AUR 和官方仓库混称为全系统更新。

### 5.2 工作窗口

保留 Niri 和现有快捷键语义。对照旧 PR 确认 `Super+Q`、方向切换、列宽切换、全屏、概览等习惯，不照抄新 shell 的示例快捷键覆盖它们。用户现在已接受键盘关闭，不擅自为所有窗口加厚标题栏。

默认仍允许半宽、三分之一、三分之二及整宽列。常见工作链为 Neovim → Codex → 浏览器 → 运行终端，使用 Niri 自然横向延伸，**不强行把四个窗口挤在一屏**。工作区沿用现有编号 / 名称起步，普通应用不因类别被自动搬走；不要为这次设计重新发明工作区管理规则。

已有图形提示可点击；键盘聚焦可见，Esc 行为一致。弹层关闭后恢复原焦点。键盘输入法、中文候选、拖动滑块、弹出菜单都必须在真实会话中验证；没有装饰按钮不等于可以牺牲基本可发现性。

## 6. 设置：优先统一真正的操作流程

顶栏、控制中心和它的子页共享同一套组件 / 状态，不把设置按钮做成启动外部工具的漂亮封面。

| 区域 | 核心流程与状态 |
| --- | --- |
| 网络 | Wi-Fi 扫描、已连接与已保存网络、连接 / 断开、密码与明确错误；有线链路与连接状态；同时有线和无线时显示各自状态及实际默认路由，不用一个图标误导。 |
| 蓝牙 | 开关、已配对设备、搜索 / 配对、连接 / 断开、设备忙与失败状态；可用时才显示耳机电量。 |
| 声音 | 输出 / 输入设备、默认设备、音量和静音；说明并展示当前应用流与输出关系，不把“改系统默认”冒充“全部应用已切换”。 |
| 常亮 | 明确的开启状态、可逆的关闭操作；与现有锁屏 / 空闲逻辑一致，不能因一次打开播放器而永久取消锁屏。 |
| 会话 | 锁屏、睡眠、注销、重启、关机；破坏性操作有确认，不忽略系统阻止项，不自行强制结束任务。 |

蓝牙连接成功不等于音频已经路由到该耳机；连接和选择输出两个步骤应清晰可见。不得悄悄改应用路由、强制断开其他网络或删除凭据。

**统一范围分级：** 桌面外壳和高频设置必须真正统一；Kitty、Neovim、LazyGit 与支持主题的系统应用共享视觉语义；浏览器、第三方应用和网页在官方支持范围内协调，不承诺所有工具包像素一致，不用脆弱注入强改所有应用。默认不强制反色 PDF、图片和网页内容。

普通 Wi-Fi / 蓝牙 / 声音流程不能以 pavucontrol / Blueman / nm-connection-editor 外观换色作为最终交付。复杂企业网、特殊路由等确实不支持的情况，可以保留清楚标注的 Advanced 入口，不能显示无效自制按钮；校园网络所需认证方式先探测，不降低证书校验来图省事。

## 7. 实现路线：复用统一桌面基础，定制高价值部分

### 7.1 首选验证 Noctalia v5

官方当前文档包含 Niri 集成、顶栏、启动器、控制中心、媒体、音频、网络、蓝牙和应用主题；这让它成为本轮统一基础的首选验证对象，而不是已经通过用户实机验收的结论。[当前版本概览](https://docs.noctalia.dev/noctalia/)、[Niri 集成](https://docs.noctalia.dev/noctalia/compositor-settings/niri/)、[控制中心](https://docs.noctalia.dev/noctalia/control-center/)。

重要版本边界：官方将旧 Quickshell v4 文档标为 legacy，v5 为新原生运行时，配置和插件路线已不同。实施时按实际安装版本核对，不混用 `qs` 命令、旧 JSON 配置或 QML 插件教程。不要为了这项改造顺便换成其配套合成器 / greeter；只使用需要的 shell。

先在隔离环境证明：真实 Niri 下字体与缩放、现有快捷键映射、高频设备设置、播放器选择、弹层焦点与视觉定制都能满足目标，且不需要大规模 fork 上游。通过后再取代旧的默认顶栏 / 控制中心。

关闭不需要的天气、位置查询、账户同步、使用时长记录、常驻频谱和自动应用主题写入；区分“隐藏组件”和“停止相应后台服务”。不接管用户隐私或新增与本任务无关的数据收集。对网络状态检测中的外网请求明确说明，不能为装饰信息偷偷增加查询。

### 7.2 失败时的明确退路

若当前维护版本无法通过上述关键流程，或实现夜航视觉需要长期维护大型 fork，记录失败项，再用现有 Quickshell 做单一外壳：统一顶栏、启动器、控制中心和子页，服务层复用真实系统接口。不同时常驻两个顶栏或两个通知服务，不把 Noctalia 控制中心、另一套 shell 的启动器、旧 GTK 面板混成新的拼盘。

不为了抽象上的“纯净”重写 NetworkManager、BlueZ、PipeWire、登录认证或音频解码。锁屏采用经过验证的现有实现；外观协调不能牺牲 PAM / session-lock 安全。若更换锁屏，作为独立风险项进行真实锁定、恢复和失败路径验收。

### 7.3 配置治理

主题颜色、字体层级、间距和动效角色有一处权威定义，各应用使用对应映射。保持共享 / Linux 专属 / 本机覆盖分层；避免桌面取色器、shell 启动脚本、终端 OSC 序列和主题生成器相互覆盖。壁纸切换不自动改变编辑器语义配色，专辑取色只影响音乐展示区域。

安装、配置生成、部署、启动分开；记录上游版本、许可与更新方式。不在仓库直接纳入第三方完整应用源码作为个人配置。macOS 的 Kitty / Neovim 只接受明确兼容的共享修改，不宣称 Linux 图形验收代表 macOS 已通过。

## 8. 音乐：一个真实播放源，多个表现界面

### 8.1 目标架构与生命周期

```text
现有音乐服务 / 本地音乐
           ↓
真实播放器后端（队列、播放状态、设备输出）
           ↕
统一控制接口 / 媒体适配层
      ↙          ↘
轻量顶栏控制      按需打开的音乐 UI
```

这表示职责分离，不强制拆成一堆微服务。优先复用维护中的播放器和接口；后台仍需承担解码 / 网络，不能宣传成“关闭 UI 就零开销”。

MPRIS 是控制与状态接口，不是播放引擎，不保证客户端具有无 UI 模式、完整曲库 API 或独立进程。`Raise` / `CanRaise` 可用于请求显示原客户端，但自定义展示界面的打开入口和冷启动可能仍需专用 IPC / 桌面入口。[MPRIS](https://specifications.freedesktop.org/mpris/latest/)、[Raise 与 CanRaise](https://specifications.freedesktop.org/mpris/latest/Media_Player.html)。

生命周期必须区分：关闭展示窗口只关闭 / 卸载渲染器；停止音乐停止播放但不等于销毁配置；明确退出播放器才结束后端。重新打开 UI 读取当前曲目、队列和进度，不重置或复制播放实例。展示 UI 崩溃不应使音频停止。

### 8.2 保住现有音乐来源

旧 PR 已记录网易云 GTK4 播放集成。这是需要保护的既有能力，不据此假定它已具备无 UI 冷启动，也不把新设计限定为此客户端。实施前验证当前来源、登录后的真实歌曲、队列与后台行为；必要时替换客户端，但迁移不能损坏账户 / 播放列表。[旧 PR 说明](https://github.com/singlelektron/Configs/pull/3)。

优先顺序：现有来源继续可用 → 成熟播放器的隐藏窗口 / 后台模式 → 必要的小型接口适配。若必须重写网易云登录、曲库、推荐和服务 API，已经超出 dotfiles 范围，应拆成单独项目 / 后续阶段，不能默认启动这项工程。

不要用 UI 自己的浏览器音频对象与后台播放器同时播放。没有后端曲库 API 时，第一版展示真实当前曲目与后端实际提供的队列，明确标出曲库管理仍在来源客户端；不能把演示专辑架宣称为完整流媒体客户端。仅有大封面也不代表全部播放器改造已经完成。

### 8.3 两级界面

**轻量控制：** 顶栏 / 小面板快速播放暂停、切歌、显示来源、封面与真实进度。不需要先打开华丽界面。优先保留显式用户选定的播放器，其次既有音乐来源规则，再考虑其他正在播放媒体；浏览器视频不能无提示抢走控制。硬件媒体键与 UI 使用相同选择规则；允许用户改选来源。

**音乐展示页：** 使用较大的独立窗口，可最大化；封面是视觉主角，配合烟色玻璃卡片、少量景深、受控倾斜 / 抽取、稳定的歌名与队列区域。浏览与播放不强制绑定：选中专辑不擅自打断正在播放的歌。进入 / 返回有连续感但不强求跨不同进程完成昂贵的像素级变形。

高级效果优先用成熟 UI / 渲染能力完成；只有普通层次和变换无法实现核心视觉时，才引入专门 3D 渲染。真正 3D 只用于展示页，不用于调音量和关机。封面色彩可轻微影响局部环境，不影响全桌面配色。

后端不支持 seek、前后曲、封面、歌词或曲库访问时，显示真实能力状态与原因。旧客户端曾报告 `CanSeek=false`，不能通过画出一个可拖动滑块冒充已经解决。不增加循环音效、自动播放背景音乐或默认长片头。

## 9. Fancy 终端：分开“工作”和“欣赏”

普通 Kitty / Neovim 保持快速、干净：协调颜色、标签、留白和边线即可；不每开一个 shell 都运行欢迎动画、大型 ASCII 图或硬件探测，不修改 Codex 自身界面，不在输入与输出区叠装饰。保留复制、滚动、搜索、终端颜色语义以及 SSH 行为。

提供一个用户主动启动的终端仪表台入口（名称可暂定 `Observatory`）：在 Kitty 中用维护中的 TUI 工具组合 CPU、内存、GPU 利用率 / 显存 / 温度 / 功耗、进程信息；不存在的传感器显示不可用。重点是本地 AI 负载与资源余量，不把几十个表盘常驻顶栏。

可把静态系统摘要或轻量真实音频可视化作为次要装饰，但不让它们成为日常 shell 启动依赖。不新增 tmux 等第二套窗口管理层，只为排出一张好看的截图。关闭仪表台应停止它专属的采样；不能解析 Codex 的私人会话文本来伪造任务进度。

## 10. 动效和性能：用可见性与实测保证，而非相信显卡型号

用户设备具备较强图形能力，但本次未连接实机，不能保证任意效果在 4K 或 GPU 满载时流畅。GUI 主线程、合成器、显存和渲染队列仍需测量。Qt 的性能指南明确建议异步 / 事件驱动、避免阻塞每帧工作并用 profiler 定位；这些原则适用于保留的 QML 部件，其他运行时使用对应分析工具。[Qt Quick 性能建议](https://doc.qt.io/qt-6/qtquick-performance.html)。

设计约束：

- 输入和设备操作即时受理；动画可中断、可反向，不等动画播完才处理下一次点击。日常转场建议约 120–220ms，音乐展示转场约 250–450ms，均是待调参起点而非实测。
- 固定日常阅读层，不做逐字符解密、闪烁光标特效或长期跑马灯。长歌名正常省略，展开后能读全。
- 网络查询、封面下载 / 解码、目录扫描和系统命令不阻塞 UI。使用异步与缓存，不用高频启动外部进程维持动画。
- 展示 UI 不存在时不加载 3D 场景；隐藏 / 非活动时显式暂停特效和专用定时器，必要时卸载大纹理。窗口不可见不自动等于所有脚本和渲染循环停止，必须验证。
- 普通顶栏按真实状态更新；硬件监控仅在需要时约 1–2 秒采样。桌面保持安静时，不应有装饰驱动的永久高帧率重绘。
- 高负载 / 全屏游戏时优先停止持续装饰，保留输入反馈与音乐控制；先实现可见性规则与手动减少动态效果入口，不先写复杂的“AI 智能调度器”。不要默认调 GPU 时钟、内核参数或实时调度优先级。
- 音乐可视化是选配；静态壁纸和缓存材质应已足够好看。动态壁纸、全屏视频、重景深和多层实时折射不作为首版依赖。

**验收目标（不是性能承诺）：** 音乐展示以稳定 60fps 为初始目标，桌面窗口交互以实机刷新率为参照；日常点击在约 100ms 内提供反馈，暖启动音乐 UI 争取约 500ms 内出现可用内容。冷启动允许稍慢，但必须有即时反馈且音频不断。记录 p95 帧耗时 / 丢帧、进程 CPU / GPU、内存 / 显存和 GPU 功耗，避免只报平均 FPS 或“占用 1%”。

对照同一台机器、同一刷新率和相同负载测试：旧环境、仅新 shell、后台播放且展示 UI 未启动、展示 UI 打开、展示 UI 关闭后、本地模型推理、全屏游戏。每种静态状态至少观察数分钟，反复打开 / 关闭展示页至少 20 次检查增长。显示的资源统计应明确是单核归一化还是整机百分比。

GPU 满载时同时记录任务吞吐和桌面响应；设计可以降级装饰，不承诺靠 shell 为 GPU 硬性预留资源。关闭展示 UI 后其动画 / 纹理开销应明显回落；否则不能声称已达到用户要求的后台低开销。

## 11. 实施顺序与可见交付

1. **建立安全基线。** 读取实机版本、显示参数、当前服务和符号链接；记录现有关键行为与性能。备份后用独立工作目录验证，不切换用户正在使用的分支或会话。
2. **做统一外观的纵向样片。** 首选 Noctalia 维护版完成“普通工作桌面 + 展开的网络 / 声音控制中心 + 音乐展示静态骨架”三种状态。素材与演示数据必须标注。提供实际 4K 截图和短交互录屏，让用户判断整体是否有吸引力，而不是再让用户选几十个参数。样片反馈前不要全面推广主题。
3. **打通真实高频设置与音乐生命周期。** 完成网络 / 蓝牙 / 声音 / 常亮 / 会话的真实状态与错误路径；证明顶栏控制、关 UI 播放、重开连续、浏览器不抢源。后台方案不成立时先解决，不用高级动画掩盖问题。
4. **加入夜航的关键表现。** 在已可用基础上完善音乐展示页的材质、封面空间关系和少量高级转场；统一应用映射，加入按需终端仪表台。无任务收益的装饰可舍弃。
5. **实机回归与交接。** 进行下表验收、负载对照、恢复测试与平台说明；按阶段提交。实施 PR 继续保持 draft，直到用户实际使用过；本文届时拆入长期文档或删除，避免 TEMP 变成另一份过时事实来源。

不要同时交付三套完整主题让用户继续陷入选择，也不要在完成前不断询问微观色号。对无法从实机或现有资料判断、确实阻塞的音乐来源 / 素材许可等问题集中说明；其他小决策按本文原则自主完成并展示。

## 12. 验收清单

| 场景 | 通过标准 |
| --- | --- |
| 视觉一致 | 顶栏、启动器、通知、控制中心及网络 / 蓝牙 / 声音子页在同一画面中像同一套产品；不是仅同色。第三方例外有明确边界。 |
| 长时间工作 | 4K 下中文、代码、diff、Markdown 与普通终端输出清楚；半透明保留；没有常驻干扰动效；原快捷键、输入法和 Neovim 操作不退化。 |
| Niri 与焦点 | 常见四窗口任务链自然滚动；弹层不改变窗口位置；Esc / 外部点击关闭后焦点正确；键盘和已有图形入口控制同一操作。 |
| 网络 | Wi-Fi 连接、取消、错误密码、不可用、网络服务重启、有线拔插、双网络状态均真实；不记录密码，不悄悄破坏已有配置。 |
| 蓝牙与声音 | 耳机配对、连接、断开、设备热移除、输出切换和音量均实机验证；默认设备与应用流路由不会混淆。 |
| 常亮与会话 | 常亮可逆；锁屏与恢复安全；注销 / 重启 / 关机有确认；不自动强制结束任务或切换默认会话。 |
| 音乐轻量路径 | 展示 UI 从未打开时可恢复播放；关闭后继续播放；媒体键与顶栏一致；停止 / 暂停 / 失败区别清楚。 |
| 音乐展示路径 | 从顶栏打开延续当前曲目 / 进度 / 队列，不重播、不双实例；关闭 / 重开 / UI 崩溃不影响后端；能力缺失不伪造。 |
| 多播放器 | 浏览器播放视频不无提示抢走音乐控制；显式选择保持到来源消失或用户改选；热移除后合理回退。 |
| 性能 | 记录负载对照与帧时间；关闭 UI 后装饰开销回落；本地 AI / 游戏压力下可降级且输入、音乐仍可用；没有只凭硬件型号作保证。 |
| 恢复与范围 | 只部署受管文件；测试恢复；保留本机其他会话；不新增重复 shell / 通知服务；不破坏 macOS / SSH，不提交任何个人状态。 |

本轮文档工作没有运行 Linux GUI、音乐、4K、输入法或性能测试。现有 PR 中的验证属于旧实现的记录，不能作为本方案已实现或已通过的证据。
